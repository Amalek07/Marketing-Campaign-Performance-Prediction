# 📊 Multi-Brand Marketing Campaign Performance Analysis and Prediction

## 📌 Project Overview

This project is a **Multi-Brand Marketing Campaign Performance Analysis
and Prediction System** developed to analyze marketing campaign
performance across three beauty and cosmetics brands:

-   **Nykaa**
-   **Purplle**
-   **Tira**

The project combines **Data Cleaning, Feature Engineering, Exploratory
Data Analysis (EDA), Machine Learning, and Streamlit deployment** into
one end-to-end marketing analytics workflow.

The system has two main machine-learning objectives:

1.  **Regression:** Predict campaign **Revenue**.
2.  **Classification:** Predict whether a campaign is **Profitable or
    Loss-making** using `Profit_Flag`.

A Streamlit application provides an interactive prediction engine and an
EDA dashboard.

------------------------------------------------------------------------

## 🎯 Project Objectives

-   Combine campaign datasets from Nykaa, Purplle, and Tira into a
    single master dataset.
-   Clean and preprocess missing, inconsistent, and numerical data.
-   Recover important financial fields where sufficient information was
    available.
-   Create useful marketing and financial features.
-   Analyze brand, campaign strategy, channel, customer-segment, funnel,
    and financial performance.
-   Identify relationships between campaign metrics and business
    outcomes.
-   Build machine-learning models for revenue prediction and
    profitability classification.
-   Compare baseline models and develop a final trained model pipeline.
-   Save trained models and preprocessing artifacts using Joblib.
-   Build an interactive Streamlit application for live campaign
    prediction and EDA visualization.

## Numerical Variables

Numerical campaign fields include:


------------------------------------------------------------------------

# 💰 3. Financial Data Recovery

Financial fields were handled using relationships between:

``` text
Revenue
Acquisition_Cost
Conversions
ROI
```

The preprocessing implementation uses the relationship:

``` text
Revenue = Acquisition_Cost × Conversions × (1 + ROI)
```

This relationship was used to recover missing financial values when
enough related variables were available.

Examples:

### Revenue recovery

If Revenue is missing but Acquisition Cost, Conversions, and ROI are
available:

``` text
Revenue =
Acquisition_Cost × Conversions × (1 + ROI)
```

### Acquisition Cost recovery

If Acquisition Cost is missing:

``` text
Acquisition_Cost =
Revenue / [Conversions × (1 + ROI)]
```

### ROI recovery

If ROI is missing:

``` text
ROI =
(Revenue - Acquisition_Cost × Conversions)
/
(Acquisition_Cost × Conversions)
```

Remaining financial missing values are filled using brand-level medians.

# 📐 4. Feature Engineering

Several new features were created to make the dataset more useful for
marketing analysis and machine learning.

## Total Spend

``` text
Total_Spend =
Acquisition_Cost × Conversions
```

## Profit

``` text
Profit =
Revenue - Total_Spend
```

## Profit Flag

The project defines:

``` text
Profit_Flag = 1 → ROI >= 1.0
Profit_Flag = 0 → ROI < 1.0
```

Therefore:

``` text
1 = Profitable
0 = Loss / Sub-optimal
```

# 📈 5. Marketing Funnel Features

## Click-Through Rate


## Lead-to-Conversion Rate

## Conversion Rate

``` text

(Conversions / Clicks) × 100
```

Zero denominators are handled safely.


A separate:

# ⚠️ Important Modeling Consideration

The current project implementation is designed as a
**campaign-performance prediction system**, not a strict pre-campaign
forecasting system.

Some model inputs are campaign-performance variables such as:

``` text
Clicks
Leads
Conversions
CTR
Conversion Rate
Revenue
ROI
```

These values may only become known during or after a campaign.

In addition, the preprocessing implementation uses the relationship:

``` text
Revenue = Acquisition_Cost × Conversions × (1 + ROI)
```

Therefore, Revenue and ROI are mathematically related to the financial
outcome.

For this reason, the reported final ML scores should **not be
interpreted as proof that the system can predict future campaign revenue
before any campaign activity occurs**.

For a strict pre-campaign model, only information available before
campaign launch should be used, such as:

``` text
Brand
Campaign Type
Target Audience
Customer Segment
Language
Planned Duration
Planned Budget/Acquisition Cost
Planned Marketing Channels
```

This distinction is important when presenting the project in an
interview or academic evaluation.
